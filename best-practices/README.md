# best-practices/ — the TASTE layer (judgment, prose)

Where **JUDGMENT** lives: genre beat structures, motion taste, the one-idea
principle, story spines. This is prose, not code. Mechanics live in `lib/`.

**This layer starts nearly empty on purpose.** It holds only this README and a
stub per genre. The deployment fills it as taste is earned. Do not seed it with
opinions copied from elsewhere.

## Two sources of authority (don't confuse them)

- **Framework mechanics** → the official `hyperframes` skills. Authoritative for
  data attributes, the timeline contract, scene-transition rules, layout,
  quality gates. On a framework-fact conflict, **the official skill wins.**
- **Marketing / brand judgment** → this directory. On a taste conflict,
  **best-practices + recent learnings win.**

## How this layer grows (the ratchet, taste half)

- A learning in `learnings/` that recurs **2+ times** is PROMOTED into the
  relevant genre file here.
- Promotion is **proposed to the human, never silently applied.**
- **Recent learnings outrank older best-practices on conflict.** If a fresh
  learning contradicts a line here, the learning wins until this file is
  updated.

## The one non-negotiable already true

Every video answers to a **single-sentence message** (what the viewer should
understand after watching). One idea per video. Everything else here is earned.

## Genre stubs

`product-launch`, `feature-demo`, `explainer`, `testimonial`,
`social-teaser`, `brand-story`. Each is an empty scaffold with the same
sections, waiting to be filled from real, verified work.
